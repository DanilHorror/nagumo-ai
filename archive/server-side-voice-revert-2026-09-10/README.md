# Архив клиентского голосового пайплайна — откат на сервер (11.09.2026)

Этот архив создан по тому же правилу проекта, что и `archive/pre-client-pivot-2026-09-10/`
(см. её README) — "ничего не удалять безвозвратно". Причина отката подробно объяснена
в техническом задании (docs/SPEC.md, раздел 5): перенос голосового
пайплайна на клиент 10.09.2026 был ошибкой объёма — экономия на аренде GPU нужна
ТОЛЬКО будущему LLM-инференсу (раздел 6), а GigaAM (STT) и Piper (TTS) лёгкие, без
GPU, и должны были остаться на сервере с самого начала.

## Что здесь есть (точный текст файлов на момент удаления — без потерь)

Все три файла просто ПЕРЕМЕЩЕНЫ (`git mv`-эквивалент) из
`verity-client/src/main/java/ru/nagumo/verity/client/voice/`, без единой правки
содержимого — в отличие от прошлого архива, здесь нет проблемы "не сохранился точный
текст": эти файлы существовали в рабочем дереве прямо перед архивацией.

- `MicrophoneCapture.java.archived` — прямой захват микрофона через
  `javax.sound.sampled.TargetDataLine` (в обход Simple Voice Chat — раздел 11 ТЗ
  ревизии 10.09.2026 показал, что клиентский API SVC не даёт доступа к сырому
  микрофонному потоку игрока вообще, `MicrophonePacketEvent` стреляет только на
  сервере). Не нужен теперь: сервер получает микрофон через сам SVC, у клиента
  больше нет собственного захвата.
- `CompanionVoicePlayback.java.archived` — проигрывание синтезированной Piper речи
  через `javax.sound.sampled.Clip` напрямую на клиенте (в обход звукового движка
  Minecraft И в обход SVC). Не нужен теперь: озвучка идёт с сервера через
  позиционный SVC-канал (`LocationalAudioChannel`) прямо на клиента-слушателя.
- `VoicePipeline.java.archived` — клиентский оркестратор: микрофон → `UtteranceDetector`
  → STT (`GigaAmClient`) → проверка имени компаньона (regex по `NagumoClientConfig.
  companionName`) → эхо-ответ → TTS (`PiperClient`) → воспроизведение → HUD-состояния.
  Его роль теперь у `NagumoVoicechatPlugin` в `verity-server` — с той же логикой
  сегментации/STT/TTS (перенесённые классы `UtteranceDetector`/`SilenceTrimmer`/
  `PcmResampler`/`WavUtil`/`GigaAmClient`/`PiperClient`/`WhisperClient` не тронуты,
  просто сменили пакет на `ru.nagumo.verity.server.voice`), но без микрофонного
  захвата (теперь через SVC, не `javax.sound.sampled`) и без проверки имени (см. ниже).

## Что НЕ было архивировано, а написано заново

`NagumoVoicechatPlugin.java` в `verity-server` — не восстановление, а новый файл.
Старая (до-миграционная) версия этого файла уже была безвозвратно потеряна ДО этого
отката — см. раздел "Что здесь НЕТ" в `archive/pre-client-pivot-2026-09-10/README.md`,
где это уже задокументировано. Новый файл написан по словесному описанию задачи и с
API voicechat-api 2.6.20, заново сверенным по содержимому jar-а (тем же способом, что
использовался для `HudElementRegistry` в Milestone 1), а не по памяти о старых
сигнатурах. Главное отличие от утраченной версии: озвучка идёт через
`LocationalAudioChannel` (позиция игрока), а не через `EntityAudioChannel`
(привязка к сущности-компаньону) — сущности-компаньона в мире больше нет с Milestone 1,
этот путь физически недоступен.

## Проверка имени компаньона — временно отключена, не удалена

И в `VoicePipeline.java.archived` (клиентская версия, была включена), и в новом
серверном `NagumoVoicechatPlugin` есть код проверки "встречается ли имя компаньона в
распознанном тексте" (`mentionsName`/`mentionsCompanionName`, идентичная regex-логика
с историей ещё от `CompanionAddressing.mentionsName`, см. первый архив). В новом
серверном файле она оставлена как невызываемый приватный метод с явным
`// TODO: временно отключено 10.09.2026 по просьбе пользователя` — компаньон сейчас
отвечает на ЛЮБУЮ распознанную реплику своего владельца, пока точность STT не
проверена вживую. Включить обратно — раскомментировать три строки в
`NagumoVoicechatPlugin.processUtterance`.

## Открытый пробел после отката (не решён в рамках этой задачи)

`companionEnabled`/`modelTier` в клиентском конфиге (`NagumoClientConfig`) сейчас НЕ
влияют на серверный голосовой пайплайн — сервер ничего не знает о клиентских
настройках игрока и продолжит обрабатывать его микрофон, даже если тот выключил
компаньона на клиенте. При полностью клиентском пайплайне (10.09.2026) выключение
реально останавливало захват (`VoicePipeline.stop()`, см. архивную версию). Синхронизация
этого состояния клиент→сервер — отдельная задача на будущее, см. docs/SPEC.md, раздел 11.
