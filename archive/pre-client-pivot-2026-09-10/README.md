# Архив кода до перехода на клиентского компаньона (10.09.2026)

Этот архив создан по запросу — "мы так долго настраивали эту механику, она нам
понадобится потом, не удаляй полностью". Ниже — что реально удалось сохранить, а
что нет, и что стоит сделать, чтобы это больше не повторялось.

## Что здесь есть (полный, точный текст файлов на момент удаления)

- `CompanionRegistry.java.archived` — реестр компаньонов сервера с проверкой
  уникальности имени среди ВСЕХ игроков (убрано в Milestone 1).
- `CompanionAddressing.java.archived` — определение адресата обращения: любой
  игрок мог обратиться к любому компаньону поблизости по имени (убрано в
  Milestone 1).
- `VerityServer.java.archived` — точка входа сервера в старой архитектуре: спавн
  сущности-компаньона в мире, обработчик ChatQuery с адресацией (убрано в
  Milestone 1).

Эти три файла я восстановил из полного текста, который сохранился в переписке —
воспроизведены точно, без потерь.

Полный текст этих файлов не сохранился в переписке (был показан только частями/

## Главная причина потери — в проекте НЕТ git

Я проверил папку проекта: есть `.gitignore`, но самого `.git` (репозитория) нет.
Это значит, что все изменения делались прямо на живых файлах без истории версий —
удалённое пропадает без следа, если только не сохранено отдельно (как в этом
архиве).

**Рекомендация:** прежде чем делать любые следующие изменения, стоит
инициализировать git в папке проекта и сделать первый коммит текущего
состояния. Дальше каждое изменение можно коммитить
отдельно — тогда ничего похожего больше не потеряется, и любой откат станет
делом одной команды (`git checkout` / `git revert`), а не ручного архива.

## Что стоит проверить у себя (может помочь восстановить остальное)

Если папка `Desktop` синхронизируется с OneDrive — у OneDrive есть история
версий файлов, которая могла сохранить старые версии удалённых файлов
независимо от git. Также если открывал проект в IntelliJ IDEA (или другой
JetBrains IDE) — у них есть встроенная "Local History", которая автоматически
хранит версии файлов за последние недели, отдельно от git и от того, было ли
изменение закоммичено. Стоит проверить оба варианта, если действительно нужен
именно оригинальный код GeckoLib-сущности и SVC-плагина, а не пересказ логики.
