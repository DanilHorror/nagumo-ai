# План действий — Verity / НАГУМО ИИ

Основано на техническом задании проекта. Этот документ — рабочий план по этапам, обновляется по ходу проекта.

## Этап 0. Дозакрыть ТЗ — ЗАКРЫТО ✅

- [x] **Личность и промпт (раздел 8 ТЗ)** — решено: без лора; 4 переключаемых пресета характера (дефолт «Дружелюбный и живой»), 3 переключаемых пресета отношения к посторонним (дефолт «так же дружелюбно»), формат ответа зависит от вопроса. Переключает только владелец.
- [x] Синтаксис команд: `/nagumo name <имя>`, `/nagumo style <preset>`, `/nagumo style-strangers <preset>` (точное имя последней — можно поправить на этапе кода). Mod id: `nagumo`.
- [x] Версия Minecraft/Fabric: **26.2**, Fabric Loader 0.19.3, Fabric API 0.152.x, Loom 1.17, Gradle 9.5.1. (26.3 в Pre-Release на 08.09.2026 — если станет стабильной к старту кода, стоит перепроверить и перейти на неё.)
- [x] Алгоритм генерации дефолтного позывного: 4–5 симв., псевдо-читаемая заготовка + leet-замены (E→3, A→4, S→5, I→1, O→0), минимум 1 буква + 1 цифра.
- [x] Коллизия имён: уникальность имени обязательна и проверяется при генерации/переименовании.
- [x] Радиус обращения по тексту: 16 блоков (конфигурируемо), голос — по дальности SVC.

Раздел 8 в ТЗ помечает несколько мелких открытых нюансов (реакция на обращение по старому имени, частота обращения по нику, реакции на игровые события) — они не блокируют разработку, дорабатываются по ходу play-теста в п.7 этапа 4/6 ниже.

## Этап 1. Скелет проекта

- [ ] Репозиторий, структура модулей: `verity-common`, `verity-client`, `verity-server` (Fabric Loom 1.17, Gradle 9.5.1, MC 26.2).
- [ ] `verity-common`: определения сетевых пакетов из раздела 9 ТЗ (пока как заглушки/DTO).
- [ ] `verity-client`: сущность-заглушка (куб/плейсхолдер), подписка на пакеты сервера.
- [ ] `verity-server`: спавн сущности на игрока при входе, генерация дефолтного позывного, команды `/nagumo name`, `/nagumo style`, `/nagumo style-strangers`, проверка уникальности имени.
- [ ] Сквозная проверка связки клиент-сервер: эхо-ответ без LLM (сервер шлёт `ShowText`/`PlayAnimation` в ответ на `ChatQuery`).

## Этап 2. Сущность и рендер

- [ ] Подключить GeckoLib.
- [ ] Финальная модель и анимации компаньона (можно параллелить с этапом 3-4, не блокирует логику).
- [ ] Синхронизация имени над сущностью (vanilla CustomName или свой `SetCompanionName`).

## Этап 3. Голосовой пайплайн

- [ ] Интеграция с Simple Voice Chat (API, позиционный звук).
- [ ] Поднять локальный Whisper (STT) и Piper (TTS) на сервере.
- [ ] Двухэтапная схема распознавания имени: лёгкий фоновый проход (VAD + быстрый STT) → полноценный Whisper при срабатывании.
- [ ] Определение адресата: поиск имени среди компаньонов в радиусе от говорящего (раздел 2 ТЗ), не только «свой».
- [ ] Атрибуция реплики: identity говорящего (никнейм/UUID) сопровождает транскрипт до `brain`.

## Этап 4. Модуль `brain` (LLM)

- [ ] Прямой вызов одной локальной LLM (без гибридной маршрутизации) с системным промптом из раздела 8 ТЗ — сквозной сценарий голос → STT → LLM → TTS.
- [ ] История диалога на пару (компаньон, собеседник), с флагом владелец/посторонний и текущим стилем компаньона в контексте.
- [ ] Гибридная маршрутизация: fallback на платный облачный API при таймауте/ошибке локальной LLM.
- [ ] Двухуровневый rate-limiting: по говорящему и по компаньону-получателю; общая очередь с таймаутами.
- [ ] Слой прямого поиска по данным установленных модов (индекс рецептов/механик, чтобы не гонять через LLM).
- [ ] Финальная полировка текстов системных промптов под каждый пресет личности (раздел 8) — по мере play-теста.

## Этап 5. Инфраструктура

- [ ] Машина 1: Minecraft-сервер (Fabric 26.2) + `verity-server`, VPS без GPU.
- [ ] Машина 2: GPU-инстанс под Ollama/vLLM (модель уровня Llama 3.1 8B / Mistral 7B, квантованная).
- [ ] Секреты (ключ облачного fallback-провайдера) — только в конфиге/переменных окружения сервера.
- [ ] Выбор конкретного облачного провайдера для fallback (по цене за токен).

## Этап 6. Тестирование и релиз

- [ ] Внутреннее тестирование на закрытом сервере (несколько игроков одновременно — проверка атрибуции по игроку, коллизий имён, обращения к чужим компаньонам, rate-limiting).
- [ ] Публикация клиентского мода НАГУМО ИИ (Modrinth/CurseForge — выбрать площадку).
- [ ] Финальная проверка: убедиться, что в клиентском джарнике нет промптов/логики/секретов (раздел 3 ТЗ) — например, декомпиляцией собранного джарника перед релизом.
